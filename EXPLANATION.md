# Summify — Complete Application Explanation & Technical Architecture Guide

## 1. Executive Summary

**Summify** is an end-to-end, production-grade **AI Document Structuring & Trustworthy RAG (Retrieval-Augmented Generation) Engine**. It addresses a critical problem faced by technical teams and researchers: messy, fragmented notes scattered across multiple files (`.md`, `.txt`, `.docx`, `.pdf`) with overlapping information, inconsistent formatting, and no unified structure.

Summify automatically:
1. **Ingests & Normalizes**: Extracts raw text while preserving heading hierarchies across multiple document formats.
2. **Chunks & Categorizes**: Intelligently chunks text along semantic headings and classifies sections into a standardized engineering taxonomy (`concept`, `setup/install`, `config`, `api-reference`, `example`, `troubleshooting`, `faq`, `other`).
3. **Deduplicates & Synthesizes**: Merges redundant content across files into a unified document with an automated Table of Contents and source traceability footers.
4. **Exports**: Formats the unified document into clean **Markdown (`.md`)**, **Microsoft Word (`.docx`)**, and **Adobe PDF (`.pdf`)**.
5. **Session-Scoped RAG Chat**: Indexes all document chunks into an isolated vector database and provides interactive Q&A.
6. **Faithfulness & Hallucination Prevention**: Audits every answer generated by the LLM against retrieved context. If an answer cannot be proven by the uploaded documents, Summify automatically enforces a strict refusal statement: *"This isn't covered in the material you provided."*

## 3. Deep Dive into Core Pipeline Modules

### 3.1 LLM Interface (`llm/client.py`)
- **Purpose**: Provides a unified, abstracted interface for interacting with LLM backends (**Groq Cloud** or **Ollama Local**).
- **Key Features**:
  - Automatically reads settings from `config.yaml` or `.env`.
  - Supports structured JSON outputs (JSON mode / Pydantic schema enforcement).
  - Implements response caching to reduce redundant API cost and execution latency.
  - Built-in retry logic with exponential backoff for network resilience.

### 3.2 Multi-Format Ingestion (`pipeline/ingest.py`)
- **Purpose**: Converts disparate file types into uniform document objects while preserving structural context.
- **Supported Formats**:
  - **Markdown (`.md`)**: Parses headings (`#`, `##`, `###`) and raw body blocks.
  - **Plain Text (`.txt`)**: Detects implicit section titles and line breaks.
  - **Word (`.docx`)**: Uses `python-docx` to extract styled headings (`Heading 1`, `Heading 2`) and body paragraphs.
  - **PDF (`.pdf`)**: Uses `pypdf` / `pdfplumber` to extract text while isolating extraction errors per file.

### 3.3 Boundary-Aware Chunking (`pipeline/chunk.py`)
- **Purpose**: Splits long documents into manageable, semantically coherent text segments suitable for LLM processing and vector embeddings.
- **Key Features**:
  - **Heading Breadcrumb Tracking**: Tracks active heading chains (e.g., `Installation > Environment Setup > Windows`).
  - **Semantic Boundaries**: Avoids cutting sentences or paragraphs in half. Respects natural boundaries like headers, double line breaks, and code block fences.
  - **Configurable Token Caps**: Enforces token limits (`max_chunk_tokens: 500`) with overlap (`overlap_ratio: 0.15`).

### 3.4 Zero-shot Taxonomy Classification (`pipeline/classify.py`)
- **Purpose**: Categorizes each chunk into a standard engineering taxonomy so the document can be organized systematically.
- **Taxonomy Categories**:
  - `concept`: Fundamental concepts and architectural explanations.
  - `setup/install`: System requirements, dependencies, and installation steps.
  - `config`: Environment variables, configuration files, and settings.
  - `api-reference`: Endpoint specifications, function signatures, and parameter tables.
  - `example`: Code samples and usage walkthroughs.
  - `troubleshooting`: Common errors, debugging steps, and fixes.
  - `faq`: Frequently asked questions and answers.
  - `other`: General or unclassified notes.

### 3.5 Synthesis & Export Engine (`pipeline/structure.py`)
- **Purpose**: Assembles disparate, classified chunks into a cohesive, non-redundant unified document and exports it to multiple standard formats.
- **Key Features**:
  - **Cross-File Deduplication**: Calculates cosine & Jaccard similarity across chunks from different input files. Merges near-duplicate passages to avoid repeating information.
  - **Automated Table of Contents (TOC)**: Builds a dynamic, numbered Table of Contents based on taxonomy sections and section subheadings.
  - **Source Traceability Footers**: Appends source file provenance to each section so users know exactly which uploaded file provided the information.
  - **Multi-Format Exports**:
    - **Markdown (`.md`)**: Standard styled text with clean heading tags.
    - **Word (`.docx`)**: Generated using `python-docx` with professional font typography, headings, tables, and bulleted lists.
    - **PDF (`.pdf`)**: Generated using `reportlab` with page layout styling, headers, and formatted paragraphs.

### 3.6 Session-Scoped Vector Index (`pipeline/index.py`)
- **Purpose**: Stores chunk embeddings in **ChromaDB** for fast similarity retrieval during RAG Q&A.
- **Privacy & Isolation**: Every user session receives a unique session ID (`session_<uuid>`). Vector index collections are strictly isolated per session, preventing cross-user or cross-project data contamination.

### 3.7 Conversational RAG Q&A (`pipeline/chat.py`)
- **Purpose**: Enables interactive multi-turn Q&A over the ingested documents.
- **Key Features**:
  - Retrieves top-\(K\) relevant document chunks using vector similarity search.
  - Passes conversation context and retrieved passages to the LLM.
  - Formats grounded answers with explicit citations referencing the originating file and heading path (e.g., `[Source: install_guide.md > Prerequisites]`).

### 3.8 Faithfulness & Refusal Engine (`pipeline/faithfulness.py`)
- **Purpose**: Ensures zero factual hallucinations in RAG answers.
- **Verification Mechanism**:
  1. Audits the generated answer against the retrieved passages.
  2. Measures factual overlap and claim verification confidence.
  3. If the answer contains ungrounded claims or hallucinated facts, Summify triggers an immediate refusal override:
     > *"This isn't covered in the material you provided."*

### 3.9 State Machine Orchestrator (`graph/build_graph.py`)
- **Purpose**: Wires the pipeline steps into a deterministic state graph using **LangGraph**. Maintains process state (`LucidocState`) across ingestion, chunking, classification, structuring, and indexing.

### 3.10 Session & Lifecycle Manager (`session/manager.py`)
- **Purpose**: Manages ephemeral session directories under `data/sessions/<session_id>/`.
- **Key Features**:
  - Caches exports (Markdown, Word, PDF) on disk to avoid re-generating documents on repeated UI interactions.
  - **1-Click Teardown**: Deletes disk artifacts and drops ChromaDB vector collections when a user clicks "Delete Session".

### 3.11 Modern Web Interface (`app/main.py`)
- **Purpose**: Provides a clean, minimalist web application built with **Streamlit**.
- **Design Philosophy**: Uses a light, modern Stripe/Linear-inspired aesthetic with curated typography, high-contrast UI controls, responsive tabbed navigation, and integrated live RAG chat.

## 4. Technology Stack Overview

| Category | Technology | Usage |
| :--- | :--- | :--- |
| **Frontend UI** | Streamlit | Web application framework with custom CSS styling |
| **Orchestration** | LangGraph | State graph execution pipeline |
| **LLM Inference** | Groq API / Ollama | Hosted fast cloud inference or offline local LLM execution |
| **Vector Index** | ChromaDB | Session-scoped vector embeddings and retrieval |
| **Document Parsers** | `python-docx`, `pypdf`, `pdfplumber` | File ingestion and text extraction |
| **Export Engines** | `python-docx`, `reportlab` | Generation of Word (`.docx`) and PDF (`.pdf`) files |
| **Evaluation** | Pytest, Custom Eval Harness (`eval/metrics.py`) | PRD verification and accuracy testing |

## 5. Summary of Key User Flows

1. **Ingest & Process**: User uploads files in **Tab 1** -> Clicks **Generate Structured Document** -> LangGraph pipeline runs -> Outputs consolidated document.
2. **Review & Export**: User navigates to **Tab 2** -> Views Table of Contents & Document Sections -> Downloads formatted `.md`, `.docx`, or `.pdf` with one click.
3. **Trustworthy Q&A**: User opens **Tab 3** -> Asks questions -> Receives grounded answers with file citations, backed by automated hallucination refusal safety checks.
